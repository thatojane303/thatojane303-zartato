Token Design

What is implemented in the contract versus what remains design notes only.

Implemented

  • ✓ Fixed supply of 1,000,000,000 ZRT (18 decimals)
  • ✓ Full supply minted once to deployer at deployment
  • ✓ Public mint and burn revert
  • ✓ Standard ERC-20 transfer / approve / allowance
  • ✓ 17 Hardhat tests covering fixed-supply rules

Not Implemented

  • – No commodity reserve or redemption right
  • – No on-chain price peg or oracle
  • – No Aerodrome pool, LP lock, or vesting
  • – No staking, yield, or fees
  • – No live market-data connection
Note: Earlier notes mentioned a 40% liquidity / 15% team / 45% community split. That is an unimplemented draft only. The deployer currently receives the full supply. Do not treat proposed percentages as live tokenomics.

What You Can Learn

ZarTATO is intentionally simple so the educational value stays clear.

Solidity & OpenZeppelin

Fixed-supply ERC-20 pattern, Ownable, and deliberately reverting mint/burn entry points.

Base L2 Deployment

Hardhat config for Base Sepolia and Base mainnet, deployment scripts, and network awareness.

🧪

Testing Discipline

17 tests that assert name, symbol, supply, transfers, and that mint/burn always revert.

🔄

CI with GitHub Actions

Compile + test workflow that runs on every push and pull request to main.

Honest Documentation

Clear separation between implemented features and future ideas — critical for grants and trust.

Cultural Context

Using South African potato-market culture as a narrative layer without overclaiming real-world backing.
